Added `env.Depends(lib, env.Value(env.module_list))` on the `modules` library target, so the compiled object's rebuild decision no longer depends solely on implicit `#include`-scanning of a generated header (which proved unreliable across a `template_debug`↔`template_release` switch). **Verified empirically, not just by code review**: built `template_debug` → `template_release` → `template_debug` → `template_release` in sequence in this same tree and checked `nm` on the compiled object each time — `initialize_objectdb_profiler_module`/`uninitialize_objectdb_profiler_module` correctly present in every debug build and correctly absent in every release build, with SCons still skipping unnecessary recompiles when nothing changed.

Combined with the earlier `taa_resolve` fix, `wgsl_precompile.py` now reports **195 compiled, 0 tint failures** — the only remaining GLSL-level failure is `cluster_render.glsl` (Task 9.4's already-tracked, separately-scoped subgroup gap). `shader_corpus` 13/13, `preprocessing_tests` 192/192 (+1 skip), no regressions.
